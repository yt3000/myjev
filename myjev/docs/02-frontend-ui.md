# MyJev · 02 前端设计（管理后台 B 控制台 + 测试 App C）

版本 3.1。两个前端交付物，统一硬约束：**零 CDN、内置 SVG、bootGuard 诊断条、后端不可达横幅、`node --check` 入验收**。
（裁决变更：v3.0 中位于控制台的"测试应用"视图迁出为独立交付物 C；独立 API 客户端库撤销，curl 示例入 04 手册附录。）

## 1. 通用硬性要求（R2.3）

1. 零外部资源：图表全部内置 SVG 渲染器（雷达/分组柱状/概率条/环形仪表），断网完整可用；
2. `window.onerror` + `unhandledrejection` + init try/catch → 页面顶部红色诊断条（消息+堆栈前 3 行），主体骨架仍可浏览，禁止静默白屏；
3. 启动聚合：一次 `GET /api/bootstrap`（B）或 `GET /health`（C）拿骨架数据；失败 → 黄色横幅给出对应启动命令（B：`start-all`；C：`服务后台未运行——执行 start.bat serve-all 后重试`）+ 5s 探活自动恢复；
4. 全部 fetch 10s 超时 + toast；错误读取 `error.message` 封套；长任务按钮置灰防重入。

## 3. 交付物 C · 测试 App（`myjev/app/index.html`，独立单文件，双击 file:// 即用）

**边界纪律**：只允许 `fetch http://127.0.0.1:8091/v1/systemone|/health`；不得出现任何管理端点调用（集成回归里以请求清单断言，01 §4）。

| 屏 | 内容 | 对应需求 |
|---|---|---|
| 场景一 · 零信任访问台 | 左侧 8 类身份场景卡（正常/ATO/撞库/伪造姿态/夜间高权/denylist/导出/钓鱼，含角色与资源背景描述）；右侧决策结果卡：动作大徽标 + risk 环形仪表 + 认证/权限徽章 + 硬规则接管标记 + Noul 概率条；每卡附"为什么"折叠（引用决策链字段，演示 R2.1） | R4 访问控制 |
| 场景二 · 工单业务流 | 工单输入（文本/渠道/金额/VIP）→ 三步流水线动画：路由 choice → 紧急度 score → 升级/常规分支卡片；批量模式：预置 6 张工单一键跑批出分布小柱状 | R4 业务流程 |
| 本地能力 | 决策历史（localStorage 禁用，内存态）+ **结果导出 JSON 下载**；"标记存疑"仅本地标注与导出（裁决：本轮无回灌，反馈链路属数据飞轮非目标——如需回灌请推翻此条） | — |
| 故障态 | A 不可达 → 黄条 + 启动指引 + 重试；页面自身异常 → 红条诊断（同 §1-2） | R2.3 |

演示动线文案内置（首页三句话说明 + 每场景一句背景），保证"给业务方演示无需讲解员"。
